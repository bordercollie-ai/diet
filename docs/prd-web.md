# Web/PWA 方案 PRD

## 1. 目标

提供一个可在现代浏览器运行的离线饮食记录工具，覆盖核心记录、食品、目标和 JSON 备份能力。数据默认只保存在用户设备上，不需要账号、服务器或网络连接。

## 2. 平台与限制

- 支持桌面浏览器、iPhone/iPad Safari 和 Chromium 系浏览器。
- 支持安装为 PWA；不要求 App Store 或 Apple Developer 证书。
- 使用 IndexedDB 保存本地数据；使用 Files/下载与文件选择器完成 JSON 备份。
- 浏览器无法提供与原生 HealthKit 等价的体重、运动和营养读写能力；HealthKit 功能在 Web 方案中不做或改为手动输入。
- 本地通知和 PWA 后台能力按浏览器和系统支持情况提供，不阻塞饮食记录。

## 3. MVP 范围

- 按日期和时间记录饮食，时间默认当前时间，支持编辑、删除和每日营养汇总。
- 搜索精选日本食品名称，创建、编辑和删除用户食品。
- 填写个人资料、目标体重和目标日期，按预计减重/增重速度生成每日热量目标，并支持手动覆盖。
- 导出和导入版本化 JSON；导入前校验，默认按 ID 合并覆盖，失败不修改现有数据。
- 中英文界面；食品名称支持中文、日文和英文；不要求品牌字段。
- 支持离线启动和核心记录流程。

## 4. 非功能要求

- 核心计算与备份校验可在无浏览器 UI 的确定性测试中运行。
- 不上传饮食、体重或健康数据。
- IndexedDB 写入失败、格式错误和不支持版本必须显示明确错误。
- 支持动态字体、键盘操作、语义标签和基础屏幕阅读器使用。

## 5. 验收标准

- 无网络时可以创建、编辑、删除饮食记录并看到正确汇总。
- 可以通过清晰的搜索结果搜索内置食品并创建自定义食品。
- 自动目标和手动覆盖结果正确。
- 导出后重新导入保留数据；损坏或不支持的文件不会改变现有数据。
- 可在 Safari 和至少一个 Chromium 浏览器完成构建、启动和核心流程验证。

## 6. 明确不做

- HealthKit、原生健康数据读写和必须依赖服务器的功能。
- 账号、云同步、社交、AI 识别、条码扫描和远程食品 API。
- 为不同浏览器实现复杂的通知兼容层。
